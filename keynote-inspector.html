Keynote Inspector

Drop a .key file and find the content that makes Keynote crash or crawl. Every image, video and PDF in the document is read from its header, so a multi-gigabyte deck takes seconds. Flags 16-bit and float images, HDR (gain map, PQ, HLG), HEIC, CMYK, oversized rasters, HDR and 10-bit video, heavy PDFs and the total memory the deck needs when everything is decoded at once.

What this looks for. Keynote composites every slide through Core Animation layers and draws images with Core Graphics. Anything over 8 bits per channel, anything HDR, and any float format (EXR, 32-bit PSD, float TIFF) is drawn through the 16-bit float RGBAf16 path with HDR headroom tracking, which is the path involved when Keynote aborts in TSDrawables during thumbnail or export rendering. HEIC adds an HEVC decode to every draw. CMYK and Lab force a colour conversion. Oversized rasters eat GPU texture memory on every display you attach. The fix in every case is the same, 8-bit sRGB PNG or JPEG resampled to the slide size, so the report tells you which files and nothing else. Data/ is scanned in full and Index/ is decoded far enough to read the slide tree and each slide's asset references, so every flagged file is tied to the slide number you see in the navigator, or to the master it belongs to.
